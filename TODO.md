# Delivery outcomes

- [x] **Secure MT4/MT5 account setup:** Users can create an account setup from the MetaAPI page using a clear account name, MT4/MT5 platform, and broker server. Signal Desk creates the account through MetaAPI on the backend and presents a MetaAPI-hosted secure configuration link so the user enters trading login/password there, not into Signal Desk. Signal Desk never stores or logs the broker password. Users can refresh account status and request a new setup link. Account ownership is scoped to the signed-in user. Removing an account from Signal Desk does not delete it from MetaAPI. The integration can provision accounts and read account status, but it does not place, modify, or close trades. The setup form is unavailable with user-friendly guidance until the server-only MetaAPI provisioning token is configured.
- [x] **Telegram chat search:** Add a search box directly above “Available groups & channels.” Filter chat names immediately while the user types, with a helpful no-match state.
- [x] **Telegram page copy:** Remove the MVP reference from the footer and replace it with a concise user-facing disclaimer. Replace the Render/free-tier warning under monitored chats with a simple message that monitoring may pause if the service goes to sleep.
- [x] **App-wide user-facing copy:** Remove developer/internal language, including references to Render, GitHub, environment variables, backend systems, database errors, system logs, and code jargon. Unexpected failures display understandable user-facing messages; useful validation and Telegram authentication errors remain specific and safe.
- [x] **Render auto-deployment:** Configure the existing API and static-site services to auto-deploy commits from `main` using the Render Blueprint's current commit-trigger setting. Preserve existing service names, build commands, environment, region, URLs, and deployment behavior otherwise.
- [x] **MetaAPI setup errors:** When MetaAPI rejects or cannot complete account setup, the backend returns the actual provider message in a sanitized user-facing field with its HTTP status and safe error code when available. The frontend displays that specific backend message instead of the generic 5xx toast. Unexpected internal errors still use a generic message, and tokens, broker passwords, and stack traces are never exposed.
- [x] **MetaAPI request contract and connectivity:** Use MetaAPI's documented provisioning hostname, pass the provisioning token in the `auth-token` header, and send the documented account payload (`name`, `server`, `platform`, `magic: 0`) without asking for or transmitting broker login/password. Generate the secure setup link with the documented configuration-link endpoint.
- [x] **Navigation label:** Replace the sidebar's “MetaAPI” label with “Trading Accounts.”
- [x] **Rate-limit proxy handling:** Configure the API to trust the Render reverse-proxy hop so rate limiting uses the originating client IP and no longer logs the unexpected `X-Forwarded-For` warning; do not trust all proxy hops.

**Validation:** All 16 backend regression tests pass; the frontend production build succeeds; `git diff --check` is clean; the production bundle contains no provisioning-token name or test secret; the old MetaAPI host was confirmed to fail DNS, while the corrected host responds; and Render logs show the prior requests failed before reaching MetaAPI.
